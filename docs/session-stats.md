# 会话统计：第 1–5 阶段

以 Pencil `0284edad-e5fa-4f93-9949-e82a1c39132f/untitled.pen` 的 `CWHvu`、`NK0HY` 为总览依据；单轮步骤依据 `fQbDm`，延续 `l4Swi5` 的耗时页入口和配色。旧 12–16 号稿未采用。

## 数据入口与隐私边界

`internal/session.NewReader(home, cachePath)` 加载统计检查点；`Cached()` 返回启动展示数据，不扫描日志；`Refresh(ctx)` 在后台发现并增量读取；`Aggregate(snapshot, filter)` 提供总览聚合。缓存路径由 App 设为 `~/.cache/knack/sessions.json`。

读取范围：

- Claude：`.claude/projects/*/*.jsonl`、`<session>/subagents/*.jsonl`。
- Codex：`.codex/sessions` 与 `.codex/archived_sessions` 下最多三层日期目录中的 `.jsonl` 和 `.jsonl.zst`。
- Factory：`.factory/sessions` 中的 JSONL；忽略 settings、备份文件和 hook 伪用户消息。
- Cursor：明确显示“没有本地会话日志，暂不支持”。其他 Agent 没有本轮验证过的日志格式，同样不生成统计。

Claude/Codex 由随程序 `go:embed` 的 JS 流式插件转换记录，Factory 保持内建 Go format；不依赖用户插件目录，用户不能覆盖其身份或认领日志根目录（含符号链接别名）。宿主只用只读文件句柄读取这些日志，脚本本身没有文件、进程或网络 API。缓存只保存元数据、用量、时序、调用标识、Skill 名称、工具输入指纹（规范化 JSON 的 SHA-256 前 8 字节）、工具结果字节数、Skill 加载的来源 / 目录 / 估算 Token / 后续用到其目录的调用数、“本轮开头像在纠正上一轮”的布尔标记、用量去重/配对的累计数值、待确认请求元信息和读取位置；不保存提示词、思考正文、助手回复、工具参数、工具输出、压缩正文。包中没有网络访问。

每次刷新最多发现 20,000 个文件、读取 64 MiB，每文件最多读取 16 MiB；单条记录上限 4 MiB。超长行跨批次丢弃，避免卡住检查点。末尾未写完的记录等待下次补齐。达到边界、记录损坏或读取失败时，快照标记不完整并展示提示；重新扫描可继续处理积压。

未改变的文件不读正文。追加前检查已消费前缀和尾部的 SHA-256 指纹；截断、同大小改写和指纹不符时重建该文件统计。发现完整时清除已删除文件的缓存；发现失败时保留未访问文件的检查点。缓存有版本、home 隔离、128 MiB 大小限制，采用 0600 临时文件加重命名写入。快照与可变检查点不共享切片。

## 解析与计算口径

- Claude 按 `message.id` 合并流式内容块，用量各桶取最大值，避免重复累计；UUID 过滤重复记录。重试推断为同一轮内 API 错误后的下一次请求。压缩边界和合成压缩摘要不产生新的用户轮次。
- Claude 子 Agent 仅通过 `toolUseResult.agentId` 关联父轮次；无法关联时保留为 `UnlinkedSubagents`。Codex 实测 `source.subagent.thread_spawn.parent_thread_id` 能识别父会话，但不能可靠关联具体轮次，故保留父 ID 并进入该集合。子 Agent 用量计一次，不增加主会话数。
- 请求耗时使用 assistant 记录与前一条有效时间戳记录的间隔；合并的内容块累积这些间隔。生成时间以该估算耗时减去可用的 thinking 时长计算。缺少时间戳、时间倒退或 thinking 大于等于总时长时，不生成速率样本。`output_tokens / 生成时间` 和这些间隔都标为估算。
- 工具耗时使用 tool_use → tool_result。实测 `permissionDecision.source=user_temporary` 才视为人工权限确认；`config` 自动授权不计人工等待。权限等待采用整个工具间隔，属于估算，不能拆出纯确认时间。
- 回复结束到下一条真实用户消息的间隔归入 `reply` 等待。有 `away_summary` 时归入 `away`；本机该记录只有文字摘要，缺少起止时间，因此不伪造精确离开时长，也不将其重复累计为普通回复等待。
- `turn_duration.durationMs` / Codex `task_complete.duration_ms` 保留为日志报告时长；中断、超时、API 错误和压缩分别保留为事件。
- Token 归一化为不重叠的输入、输出、缓存读取、缓存写入四桶。Claude 输入本身不含缓存；Codex `input_tokens` 含缓存，需先扣除缓存桶。总 Token 为四桶之和；缓存命中率为缓存读取 / 全部输入。
- Codex 优先使用 `token_usage_record.payload.usage`，按 `response_id` 去重。没有对应记录时，用 `event_msg.token_count.payload.info.last_token_usage` 补齐请求；`total_token_usage` 只生成累计位置/去重标识，绝不作为用量相加。缺少桶视为 0，累计标识规范化后去重，避免同一历史因新增零值字段再次计数。info 为 null、last 缺失或四桶全零时不生成请求。两种来源通过累计位置及同一输入阶段的反向上报队列配对，跨批次/重启保存数值状态；原生请求保持原来的 ID、模型、结束时间和 inputTiming，先到的 fallback 不消费原生计时锚点。旧日志同样使用 inputTiming 估算耗时；仍无逐请求用量的记录不按零计。
- Codex 第一笔 `session_meta` 确定文件身份与父关联（兼容顶层 `parent_thread_id` 和 source.subagent.thread_spawn）；后续重放的父 meta 不覆盖子身份。用量另保留最近一笔 meta 的历史来源 ID。快照按「历史来源 ID＋规范化累计值」跨文件去重 fallback，优先保留原始拥有者，再选较早时间/稳定路径；原始文件不在时保留一份子日志副本，子 Agent 自己新增的累计位置仍计入。不能只按时间早于 meta 丢弃：真实重放会改写时间戳。
- Factory 实测 v2 消息含 `modelId`、tool_use/tool_result 和 thinking.durationMs，但不含用量字段，因此 Token 和 tok/s 均标为“暂不支持”。Codex 无可靠请求起止关联，tok/s 同样不支持。
- 中位数使用中间值（偶数样本取两者均值），P90 使用 nearest rank；展示样本数。按 Agent / 模型聚合、每日 Token 和常用 Skill 都来自同一快照。日期按本地时区，范围为 `[From, To)`，请求完成时间决定 Token 归属日期。
- “耗时异常”包含超过 60s 的模型请求、工具、权限等待和有明确时长的压缩，以及 API 错误、推断重试、中断、超时。普通压缩和离开摘要不自动作为耗时异常。
- `FoldLongStep` 仅在 `step > 60s && step > turn/2` 时返回 true。第 4 阶段已接入开关 UI、共享时间轴折叠和偏好持久化。

### 阶段估算和未知时间

阶段图使用时间区间的互斥归因，不直接相加并行工具或重复相加父 Agent 工具与子 Agent。扫描线优先级为：权限/回复等待 → 重试与压缩 → 子 Agent → 工具 → 思考 → 生成 → 离开相关间隔。该优先级保证已计入权限代理间隔的执行时间不会再被计入工具/子 Agent。

模型区间以请求结束时间和估算耗时构造，思考在该区间内裁剪；错误/推断重试请求整体归入“重试与压缩”，无法拆出精确退避。已有权限估算口径不变，仍包含工具执行时间；当子 Agent 与该间隔重叠时会注明“未单独计时”，真实子 Agent 日志跨度仍在调用时间线展示。

阶段总量使用主会话日志跨度。每轮范围包含附属的回复等待间隔，止于下一轮开始，避免轮间重复；它与日志报告的纯 turn_duration 不同。关联未知的子 Agent 仅按有证据的时间范围参与区间归因，不作为已知的父轮次调用关系。主会话范围之外的子 Agent 用量仍纳入详情总量，但不会扩张主会话阶段占比。

“离开相关间隔”和未归因时间单列文字，图中留白；留白不是零时长。Codex 模型阶段/速率、Factory 用量等缺失数据继续显示“暂不支持”，不使用设计示例值。没有观察到的阶段显示“未记录”。所有图表均有数值、说明或可读提示，轮次异常同时有图标和文字。

## 第 4 阶段：单轮步骤瀑布图

通过 Pencil MCP 直接读取 `fQbDm` 的结构和截图实现，沿用第 3 阶段内容区的 accent 描边、浅底及 phase-* 深浅色 token。新增 `sessionsteps.go` 负责从缓存快照构造步骤和压缩时间轴，`sessionround.go` 绘制摘要、步骤及元信息；绘制不读取日志。

### 入口和键盘

- 耗时页的“需要关注”和每轮柱图均进入对应轮次。柱图使用左右方向键移动、回车进入；单轮页提供有文字名称的“上一轮”“下一轮”，首尾禁用越界按钮，Tab 可达。
- “返回耗时”或 Esc 返回耗时 tab，保留当前轮次并将键盘焦点恢复至对应柱子。设置/确认/仓库对话框打开时不抢占 Esc。
- 步骤使用纵向焦点组：Tab 进入，向上/向下选择并同步详情；短窗口自动将聚焦行滚入视口。会话列表和详情仍各自滚动。
- 摘要展示轮次序号、开始时间、区间总耗时及该轮全部已记录模型；另列日志报告的轮次耗时。区间范围延续第 3 阶段的口径，可能包含附属回复等待，与纯 turn_duration 有区别。

### 步骤和折叠口径

- 每个模型请求、工具调用、已关联子 Agent、回复/权限等待各占一行，包含推断重试、失败请求、压缩、中断和超时事件。工具已关联子 Agent 时用子 Agent 行替代包装工具行并保留其工具元信息；权限工具与对应权限 Wait 合为一行。并行调用保留各自的起止，不能把行时长相加当作本轮总耗时。
- 模型起点使用结束时间减估算请求耗时，与第 3 阶段一致；思考/生成使用同一行内的两种 phase 颜色。Codex 缺少可靠请求计时，不伪造位置或时长。没有起止的步骤仍展示名称和文字时长，缺失值为“暂不支持”。
- `FoldLongStep` 原样决定资格：严格大于 60s，且严格大于本轮区间总耗时的一半。将满足条件的时间区间裁剪到本轮、合并交叠后，每段显示为最多 10s 的轴长度；所有行使用同一分段线性变换，保证并行调用和后续步骤对齐。真实比例使用原始时间轴。
- 折叠区间不画实心背景带；在所有行之间画两条连续的 TextMuted 中性细线，所有跨越该位置的条留出断口，符合条件的长步骤绘制双段截断条，文字仍显示原始时长，并在图上标出折叠的实际区间和时长。起点和末端标注使用原始时间，不把压缩后的显示长度当作真实耗时。
- 长时长沿用 `42m`、`6m12s`、`1h12m`，不足 1s 使用小数（不足 0.1s 为 `<0.1s`），估算值带 `≈`。短条至少 2px 以保持可见，精确值以文字为准。
- 超时事件的 Duration 仅表示超时阈值，不能倒推为执行区间；将其画为事件点，在详情中注明阈值。离开相关间隔仍标注“估算”，不把日志摘要推断成精确离开时间。

### 元信息与设置

步骤详情按类型显示适用的字段：模型/重试请求显示模型、Token 和估算 tok/s；工具显示工具名和执行状态，仅 Skill 调用显示 Skill 名；子 Agent 显示其模型/用量/速率/中断信息；等待显示等待类型或权限来源；压缩显示压缩耗时；超时/中断事件只显示相应状态。不适用的字段直接隐藏。模型请求使用互斥的输入/输出/缓存桶；子 Agent 行仅汇总该子 Agent 本体已记录请求，部分用量有明确标记。不把相邻模型请求的用量或模型归给工具调用。可解析状态没有记录时显示“未记录”，没有支持数据的字段显示“暂不支持”。权限来源直接来自已采集的 permission source/decision；人工权限间隔包含执行时间的说明保持不变。

## 第 6 阶段：Codex 读取与轮次回放

### Codex 和 Factory 没有统计的原因

每次刷新最多读取 64 MiB，原先按路径顺序分配：`.claude` 排在 `.codex`、`.factory` 前面。Claude 日志积压较大时，每次刷新都会用完预算，Codex/Factory 永远读不到，总览显示“没有可识别的会话记录”，重新扫描也无效。

- 读取预算按文件修改时间从新到旧分配，跨 Agent，最近 30 天的数据最先完整。
- 预算用完时快照标记 `More`；App 在有进度时自动继续刷新，直到积压读完，界面随进度更新。仍在写入的末行不会触发循环。
- Codex `compacted` 记录内嵌整段替换历史，可超过 4 MiB 单行上限。超长记录若属于只需时间戳和类型的 `compacted`，从前 4 KiB 恢复记录头，保留压缩事件，不再将会话标为“记录不完整”。
- 缓存版本升为 2，旧缓存会重建一次。

### Codex 请求耗时

请求从输入完成（`task_started`、用户消息或最后一个工具输出）开始，到 `token_usage_record` 结束。与 Claude 一样，这个间隔是估算值。`item_completed` 中 `Reasoning` 的 `started_at_ms`/`completed_at_ms` 是实测思考时长，生成时间 = 间隔 − 思考。Codex 模型阶段和 tok/s 不再显示“暂不支持”。

### 总览修正

- 会话指标的对比改为“较前 30 天 +N”“与前 7 天持平”“前 30 天没有会话”。
- “需要处理”的耗时异常改为与其他问题相同的行，下方列出异常最多的 4 个会话，可直接打开其轮次页；不再显示居中的孤立链接。
- Agent 表使用固定的数值列（会话、Token、缓存命中、输出速率、最近活跃），模型放在对齐的第二行；不支持的值用弱化色，零会话的行用“—”。
- 最近会话合并为两行，标题已含 Agent 和仓库时不再重复；耗时异常用图标表示。
- 每日图表说明只列出当天有用量的 Agent。逐文件读取提示汇总为一行，悬停查看，不在页面直接列出原始文件名。

### 轮次回放

会话详情的“耗时”tab 改为“轮次”，按轮展示：

- 顶部：轮数、活跃时间、等待你/离开时间；阶段条和图例只覆盖活跃时间，等待不再占 90% 以上。
- 每轮一行：序号、开始时间、用户输入的第一行、活跃耗时，以及按统一比例绘制的阶段条、模型/工具/子 Agent 次数、Token 和本轮最长的耗时异常。轮间超过 30s 的等待以分隔行显示。
- 活跃时间从轮次开始到最后一个请求、工具、子 Agent 或事件；之后到下一轮之间计为等待（有离开摘要时计为离开）。
- 打开一轮后显示“调用链”：上方是完整 prompt 卡片，下方是请求、工具、子 Agent、等待在同一时间轴上的瀑布图，每行附内容摘要（回复首行、调用的工具、命令或路径）。选中的步骤就地展开：模型请求显示思考与回复，工具显示等宽字体的输入与输出（横向滚动，不拆分路径），以及原有的元信息。超过 12 行或 1600 字的文本折叠，可展开；单段超过 64 KiB 的部分不显示。
- Claude Code 的“[Request interrupted by user]”不再开启新的空轮次，改为标记当前轮次中断。注入的上下文（system-reminder、AGENTS.md、环境信息、压缩摘要）不算作用户输入，只显示条数。

回放内容由 `session.ReadTranscript` 在打开会话时从原始日志按需读取：只读、每个文本字段上限 64 KiB、单文件读取上限 512 MiB，内容与统计按 `message.id`/`response_id` 和工具调用 ID 关联。内容只保留在内存中最近 4 个会话，不写入缓存；统计缓存的隐私边界不变。

### 总览布局收紧

总览改为卡片网格：四个指标合为一张分隔卡片；宽窗口下左列依次为每日 Token、Agent 使用情况，右列依次为需要处理、最近会话，两列各自堆叠，不再按行配对，避免较矮一侧留下大块空白。图表高度降为 136，选中日期用浅强调色底；当天说明与“最近 60 日”提示合为一行。Agent 表的数值列平分宽度，主力模型在对齐的第二行；需要处理与最近会话改为分隔线列表，最近会话显示 6 条。脚注合为一行。窄窗口（内容宽度小于 760）按卡片纵向排列，指标为两行。

### Codex 压缩与归档日志

Codex 会把较早的 rollout 原地压缩为 `.jsonl.zst`，并把归档会话放进 `.codex/archived_sessions`（同样是 `.jsonl.zst`）。此前只读取 `.jsonl`，本机 263 个 Codex 日志只统计到 55 个。现在两处都会读取：

- 使用纯 Go 的 `github.com/klauspost/compress/zstd` 解压，日志仍以只读方式打开。
- 压缩日志不会再追加内容，检查点记录解压后的偏移；受刷新预算限制时，下次跳过已解析部分继续。大小或修改时间变化时重建该文件的统计；读完后不再重复读取，重启后也一样。
- 带大附件（图片）的超长 `message` 记录与 `compacted` 一样只恢复记录头（时间、类型、角色）。记录跨刷新时，只在检查点里保留合成的记录头，不保留任何正文。
- 轮次回放同样支持压缩日志。

本机实测：Codex 主会话由 43 个增至 176 个（另有 87 个子 Agent），Token 约 2.03B，所有会话都完整，没有读取提示。Codex 自身的线程索引（`state_5.sqlite`）记录了 1857 个线程，其中约 1590 个已没有对应的日志文件，无法从日志统计。

### 统一的读取接口

此前新增一个 Agent 要改两个包里十几处分支：目录发现、解析分派、回放、能力说明、颜色和图表槽位。现在每个 Agent 是一个注册的读取格式（`internal/session/format.go`），由它提供：

- 名称与能力声明（Skill、tok/s、权限等待、工具超时与中断）以及缺失说明。界面上的“暂不支持”和说明文字都来自这些声明，不再按 Agent 名判断。
- 日志目录、文件后缀和目录规则（例如 Claude 的 `subagents`），以及子 Agent 是否能关联到父会话的具体轮次。
- 记录的时间与 ID、统计解析和回放提取。
- 解析规则版本。版本变化时只重建该 Agent 的统计缓存。

Claude/Codex 目前通过内嵌 JS 流式 format、Factory 通过 Go format 接入此接口，统计口径不变；本机真实日志重新读取的会话数与第 6 阶段一致。总览的 Agent 筛选、Agent 表、每日图表和底栏都改为从注册表生成。图表不再固定为 Claude / Codex / 其他三个槽位：有用量的 Agent 按用量排列，最多 3 个独立系列，其余合为“其他”；没有专属颜色的 Agent 依次使用三种补充颜色。

### 自定义 Agent

其他 Agent 的 JSON Lines 日志可以在 `~/.config/knack/agents.json` 中声明字段映射接入，见 [自定义 Agent](agents.md)。设计取舍：

- 声明式映射不执行代码。映射表达不了的格式用 JS 插件：外部可执行程序或 WASM 会破坏“只读、不联网”的承诺，或者对 GB 级日志太重。用户插件用纯 Go 的 moejs 执行，脚本默认接触不到本机，只能调用 Knack 暴露的只读方法。脚本运行在 Knack 自身以 worker 模式启动的子进程里：宿主调用（例如一条不返回的 SQL）不响应中断，只有结束进程才可靠。内嵌 Claude / Codex 脚本仍在主进程的 goja 里运行。
- 用户插件接管读取，输出标准记录，可用扩展 stats/replay 操作补足 Skill、子 Agent、实测思考、权限/工具结果及事件信息。用户插件仍按会话 `version` 整体重读，不做字节检查点；内嵌流式插件由宿主读取和维护字节检查点，见下节。
- 目录必须在主目录下，不能与其他 Agent 重叠，避免同一文件被两个 Agent 统计。
- 映射的哈希就是解析版本，修改映射只重建该 Agent 的缓存；从配置中移除的 Agent 不再出现在缓存快照中。
- 配置错误逐个 Agent 报告：总览底部给出提示，具体原因悬停查看；有问题的 Agent 不会加载，其余照常加载。

## Claude/Codex 内嵌 JS 迁移

`internal/session/plugins/common.js` 加上各 Agent 脚本通过 `go:embed` 发布。JS 的 readRecord 把原始记录转成扩展 stats/replay 操作；`embedded.go` 的共享 reducer 归约成统计或回放，原 `claude.go`、`codex.go` 和它们的 Go 回放分支已删除。注册身份、能力和 Note 文案来自脚本。协议字段和执行边界见 [Agent 插件协议](agents.md#扩展记录协议-v1)。

保持的语义包括 Claude 的流式用量最大值和 UUID 去重、toolUseResult.agentId 对父轮的关联、权限等待、工具超时/中断、API 错误及推断重试、压缩/离开事件、Skill 加载和注入上下文；Codex 的 response_id 用量去重、parent_thread_id 与 UnlinkedSubagents、实测 Reasoning、请求输入完成锚点、延迟轮次完成和回放条目请求关联。所有会话相关状态都在原有 Go 检查点中，重启或换批后不依赖 JS 全局变量。Factory 解析和回放规则不变。

执行取舍：内嵌脚本经过随程序审核，在主进程加锁的 goja runtime 中处理单条受 4 MiB 限制的记录，没有任何 I/O API；第三方脚本仍在有超时/内存限制的 worker。内嵌路径不受整个会话的 30 秒、128 MiB 结果和连续失败停用约束。背景扫描仍按 64 MiB/刷新、16 MiB/文件预算，最近日志优先，超大 compacted 从 4 KiB 头恢复事件，`.zst` 保留解压偏移增量恢复。未变文件读取 0 字节。代价是 JS 分配/转换成本，以及巨大归档恢复时重复解压已消费前缀；脚本缺陷也没有 worker 的崩溃隔离。取消在记录间检查。20,000 个发现文件和 128 MiB 统计缓存的原有上限不变。

版本为 `stream/1/` 加公共脚本与该 Agent 脚本的 SHA-256；修改脚本自动重建对应 Agent，修改共享 reducer 的语义需升级协议版本。旧 claude/3、codex/3 检查点在刷新时失效。用户插件的扩展记录版本为 plugin/3，字段映射与 Factory 的版本不变。

迁移验证另外覆盖：将 worker 调用限时降至 1ns 后内嵌读取仍跨批次、跨 Reader 重启完成；135 MiB 以上解压日志恢复 27 个超长 compacted 事件并读到末尾用量；两个 Reader 和回放并发共享 runtime；旧版本检查点重建；不可发现日志路径及符号链接保留；用户插件的扩展记录、能力与 Note 传递及隐私检查。原有 TestReadTranscript、TestRefreshPrioritizesRecentLogs 和 App 的行为断言未放宽。


## Codex 旧版 token_count 回补

2026-11-09 的只读核验发现：2026-07 的 33 个文件有 39,859 条 token_count，按文件内累计值去重得到 38,528 次、5,274,492,047 Token。其中 28 个文件的第一笔 meta 声明子 Agent，18 个重放父会话历史，包含父 meta 和相同累计序列；部分重放时间戳已改写。累计字段缺少 cache_write_input_tokens 与显式 0 也代表同一位置。按来源与规范化数值跨文件去重后为 6,068 次、747,384,457 Token，排除 4,527,107,590 个重复 Token；并非全部真实新增用量，也不能把全部历史前缀直接丢弃。

回补先保存为检查点中的待配对请求，只在脱离检查点的快照中加入轮次；后到的原生记录可以撤销对应 fallback，而不会改变原生计时锚点或创建多余轮次。跨文件拥有者在每次快照（含 Cached）从所有检查点重算，因此读取顺序、最近日志优先和重启不影响去重结果。状态只含 ID、累计桶、配对计数和请求统计，不保存对话正文。Codex 脚本哈希变化会重建其旧缓存；新增操作不改变其他插件已有操作的含义，Claude/Factory 不重建。

合成测试覆盖旧版单次用量、重复上报、两个上报顺序及重启、1024 字节预算下多批重启、缺失/null/全零用量、混合日志中独立的相同成本请求、子 Agent 重放及父文件缺席。真实核验只输出数值与计数，缓存使用系统临时目录，没有写入 ~/.cache/knack。
