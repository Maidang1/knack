# 诊断

侧栏「会话」下的「诊断」把会话统计和技能扫描放在一起看，回答“该改什么”。页面只读，跟随标题栏的时间范围和 Agent 筛选。唯一的写入是点「打开价格表」时，在没有价格表的情况下创建一份模板。

## 费用

按请求的模型和逐请求用量估算美元费用，请求按完成日期归属，子 Agent 的花费计入它所在的会话。

- 内置价格是 Anthropic 官方 API 的价格（美元 / 百万 Token）。缓存写入按 5 分钟缓存计，即输入价的 1.25 倍。Haiku 5.5 按 10 万 Token 以内的档位计。
- 订阅套餐、云平台和代理的实际计费不同，这里的数字只用于比较相对开销。
- 没有价格的模型不计入费用，单独列为“未定价 Token”，不会显示成 $0。`<synthetic>` 是 Claude Code 本地生成的占位回复，按 $0 计。
- 缓存节省 = 缓存读取 Token 按输入价计算时，比按缓存读取价多出的差额。

### 价格表

`~/.config/knack/prices.json` 补充或覆盖价格，单位是美元 / 百万 Token：

```json
{
  "models": {
    "gpt-6.1-sol": {"input": 1.25, "output": 10, "cache_read": 0.125, "cache_write": 0},
    "claude-opus-5-5": {"input": 4, "output": 20, "cache_read": 0.2, "cache_write": 5}
  }
}
```

模型名不区分大小写。查找时先找完整名称，再找最长的前缀；带路径或前缀的名称（如 `custom:proxy/gpt-6.1-sol`）还会再用最后一段匹配一次。改完后点「重新读取」，或者重新扫描。

## 上下文

每个会话第一个有用量的请求的输入 Token（缓存读取 + 缓存写入 + 未缓存输入）。它包含系统提示词、工具定义、指令文件、技能列表和第一条消息，可以当作开会话的固定开销的上限。表格按 Agent 和工作目录统计中位数和 P90，峰值是会话中单个请求的最大输入。失败的 API 请求不计入。

## 技能

只统计 Agent 会直接加载的目录（Agent 目录和自带目录），共享池和仓库不算。

- **常驻**：技能名和描述在每个会话技能列表里占的 Token，按字符数估算，中日韩文字约 1 字 1 Token，其他约 4 字符 1 Token。
- **90 天未调用**：只对日志里有 Skill 调用记录的 Agent 计算，其他显示“暂不支持”。调用按技能名匹配，插件技能的 `插件:名称` 也算。
- **描述问题**：缺少 SKILL.md 或 description、front matter 无法解析、软链断开、描述超过 1024 字符或短于 40 字符、front matter 的 name 与目录名不同。没有写何时使用只作为建议。
- **描述相近**：同一 Agent 下两个描述的用词重合度（Jaccard，英文按 3 个字母以上的词，中文按相邻两字）达到 0.45。

同一个技能挂到多个 Agent 时只列一次，并注明有几个 Agent。

## 技能评测

参考 Anthropic skill-creator 的两个评测维度：**触发**（描述能否让模型在该用时自己加载）和**执行**（加载后这一轮是否更顺）。这里不重跑任何东西，而是把已经发生的每一次加载当作一个样本。

- **加载**：Claude Code 的 Skill 调用（自动）和用户输入的 `/名称`（手动）；Codex 没有 Skill 工具，按 `cat`、`sed -n`、`head` 等读取 `…/SKILL.md` 的命令识别。Factory 的 Skill 调用同 Claude Code。子 Agent 里的加载算到运行它的那一轮。
- **读入**：Claude Code 在加载后注入的技能正文（以 `Base directory for this skill:` 开头）按字符估算 Token；Codex 按读取命令返回的内容估算。
- **用到自带文件**：加载之后同一轮的工具调用，输入里出现技能目录（或 `/<名称>/`）下除 SKILL.md 以外的路径。只对目录里有脚本、参考等文件的技能判断。
- **顺利**：加载后没有工具失败、这一轮没被中断、下一轮开头不像纠正（“不对”“还是报错”“still failing”等开头，只保存布尔值）。对照组是同一时段没有加载任何技能的轮次。Codex 日志不记录工具失败，失败率显示为“—”。
- **改动前后**：以 SKILL.md 的修改时间为界，比较之前和之后的加载。

结论包括：多数加载靠手动输入（描述可能没写清何时使用，只对技能目录中的技能提示）、从没用到自带文件、顺利率或失败率明显差于对照、说明过长。这些都是相关性，不是因果：难的任务本身就更容易失败。

### LLM 评测

上面的“顺利”只看有没有失败、中断和纠正。LLM 评测让模型对照一组评估标准阅读每一次加载所在的那一轮，逐条给出通过、未通过或不适用。这是诊断里唯一会把会话内容发到本机之外的功能，默认关闭。

**连接模型**：设置 →「模型」。接口选 Anthropic（Messages API，经官方 Go SDK）或 OpenAI 兼容（`/chat/completions`），填地址、模型和密钥，点「保存并测试」。地址留空用官方地址；密钥可以写成 `$环境变量名`，Anthropic 接口留空时使用环境里已有的凭据。连接保存在 `~/.config/knack/llm.json`，权限 0600。只有打开「允许把会话内容发给这个服务」之后才会发送任何内容。

**评估器**是一个技能的评估标准，分两类：

- 规则：Knack 从日志统计直接判断，不调用模型。包括这一轮没有被中断、下一轮开头不像纠正、加载后的工具调用没有失败（日志记录工具结果的 Agent）、用到了自带文件（技能目录里有其他文件时）。
- 模型：点「生成评估器」时，模型读 SKILL.md（最多前 6 万字）、技能目录的文件清单，以及最多两段这个技能的真实加载（一段顺利、一段不顺利），起草 5 到 8 条。每条都可以改写或删除，也可以自己添加。不在技能目录中的技能读不到 SKILL.md，只能手动建立。

**评审**：点「评审 N 次加载」先读取这些轮次的原始日志，显示会发送几段记录、发往哪个主机、估算多少 Token，确认后才发送。一次最多 20 次加载，从最近的开始，同时最多 3 个请求。发送的是那一轮里用户的话、助手的回复、工具的输入和输出，以及下一轮的第一句话；思考内容和注入的上下文不发送。单条消息超过 4000 字、工具输入或输出超过 1500 字时保留首尾并注明省略，整轮超过 12 万字时从中间省略整步。形如密钥的内容（`sk-…`、GitHub 令牌、AWS 访问密钥、JWT、私钥块，以及 `token=`、`password:` 等名称后面的值）先替换为“[已隐去]”，这只覆盖常见形态，不是保证。子 Agent 里的加载暂不评审。第一次请求失败就停下，已有的结论保留。

**结论**：每条标准有一句理由和一段引文。Knack 会在发送的记录里查找这段引文，找不到的标为“引文在这一轮的记录里没有找到”，这样的结论不要直接采信。改写、添加或删除模型标准后，原有结论按旧标准算，需要重新评审。

**校准**：每条结论可以标为“判对了”或“判错了”。标为判错的结论按相反的结果计入统计，最近 8 条会在之后的评审里告诉模型。“与你一致”是你核对过的结论里判对的比例，低于八成时值得先改标准的措辞。

**失败归因**：有未通过的结论后，可以点「归纳 N 条未通过的原因」。模型读 SKILL.md 和这些结论的理由、核对过的引文（对不上的引文不发送），把同一原因造成的失败归到一起，每个原因写明涉及几次加载、Agent 实际做了什么，以及对 SKILL.md 的修改建议。一次最多读 80 条，发送前同样显示估算。改完 SKILL.md 后重新评审最近的加载，看未通过的是否变少。

评估器、结论和归因保存在 `~/.config/knack/evals/<技能>/` 的 `evaluator.json`、`verdicts.json` 和 `causes.json`，文件权限 0600。结论里的引文不超过 200 字、理由不超过 300 字，其余会话内容不保存。

模型的判断同样不是因果，也会出错：它只看得到一轮的记录，标准写得含糊时结论也含糊。

### 触发评测

检查描述能不能让 Agent 在该用的时候加载这个技能、不该用的时候不加载。

**评测集**有三个来源，每条标为应触发、不应触发或不用：

- 从会话中挑选：不调用模型。加载过这个技能的轮次默认“应触发”；没有加载的轮次中，与描述用词重合的近似反例排在前面，其次是加载了其他技能的轮次，默认“不应触发”。每次约 20 条，最多读 40 个会话的原始日志，已有的提示词不重复添加。
- 让模型编写：模型读 SKILL.md（最多前 2 万字）、同一 Agent 里其他技能的名称和描述，以及已有的用例，写 8 条应触发和 8 条容易误触发的近似请求。
- 手写：输入一条请求，选应触发或不应触发后添加。

**模拟触发**：把同一 Agent 能看到的技能列表（名称和描述，按名称排序）和一条请求发给模型，问它在动手之前会加载哪个技能，每条请求单独一次调用，同时最多 3 个。列表在一次模拟里不变，Anthropic 接口会标记为可缓存。结果显示应触发的请求里加载了几条、不应触发的请求里误加载了几条，每条请求旁边写着上次模拟的选择和模型的理由。发送前显示请求数、技能数和估算的 Token，第一次失败就停下，已经返回的结果保留。

**改写描述**：模拟用的描述可以直接修改，改动只用于模拟，不写回 SKILL.md。最近一次模拟有判断错的请求时，可以点「让模型改写描述」，模型根据错例给出新描述和改动说明，填进输入框；再模拟一次就能和之前比较。最近 6 次模拟按描述列出，点一行把那次的描述填回去，满意后「复制描述」粘贴到 SKILL.md。

模拟只看名称和描述，和真实 Agent 的选择会有出入，同一条请求多跑几次结果也可能不同，适合比较几种写法的高下。评测集和模拟记录保存在 `triggers.json`，包含请求原文，权限 0600。「导出 eval_set.json」按 skill-creator 的格式（`[{"query": …, "should_trigger": …}]`）写出当前使用的请求。

设置 →「模型」里的「清除评测数据」删除所有技能的以上文件，包括导出的 `eval_set.json`。

## 会话诊断

会话页在轮次列表上方显示每次模型调用的上下文：一根柱是一次调用，按缓存读取、缓存写入、未缓存输入堆叠，压缩处有竖线。写入至少 1 万 Token 且多于读取的调用记为“缓存重建”，并给出原因：上下文压缩后、换了模型，或距上次调用的间隔（只陈述间隔，不判断缓存是否过期）。

下面列出这次会话值得看的地方，点击打开对应的轮次和步骤：

- 疑似循环、连续 3 次以上的工具失败、被中断或疑似被纠正的轮次、加载后出问题的技能；
- 大段工具结果：返回超过约 2 万字节的调用，估算之后有多少次模型调用一直带着它（到下一次压缩为止）；
- API 请求失败、超过 2 分钟的权限确认。

## 摩擦

- 失败 = 工具结果的错误标记、中断或超时。中断和超时目前只有 Claude Code 记录。
- **疑似循环**：同一轮里同一工具、同一输入连续调用 3 次以上。输入用规范化 JSON 的 SHA-256 前 8 字节比较，缓存不保存输入内容。`write_stdin`、`wait`、`BashOutput` 等轮询类工具重复调用是正常用法，不计入。旧缓存没有指纹，重新扫描后才能识别。
- **等待确认**：Claude Code 记录为“用户临时允许”的工具调用。`AskUserQuestion`、`ExitPlanMode` 等提问类工具等的是人回答问题，不计入。
- 常需确认的工具会对照「配置」页所选目录的 `permissions.allow`，没有规则的会单独提示。

## 项目

按会话的工作目录归类，汇总会话、轮次、Token、费用、工具失败率、开局中位数和常用技能。点一行查看该目录的会话，右键可以查看该目录生效的配置。

## 配置

读取在所选目录启动 Agent 时生效的配置：

| Agent | 文件 |
| --- | --- |
| Claude Code | `~/.claude/settings.json`，`~/.claude.json` 的 `mcpServers` 和该目录的本地 MCP，`~/.claude/CLAUDE.md`；项目里的 `.claude/settings.json`、`.claude/settings.local.json`、`.mcp.json`，以及从 home 到该目录每一层的 `CLAUDE.md`、`.claude/CLAUDE.md`、`CLAUDE.local.md` |
| Codex | `~/.codex/config.toml` 的 `[mcp_servers.*]`，`~/.codex/AGENTS.md`，从 home 到该目录每一层的 `AGENTS.md` |

CLAUDE.md 中代码以外的 `@路径` 导入会跟进，最多 5 层，导入文件的 Token 一并计入。MCP 只显示启动命令名或服务地址的主机名，hooks 只显示命令的第一个词。参数、环境变量和完整 URL 可能含密钥，都不显示。MCP 调用次数按日志里的 `mcp__<服务器>__<工具>` 统计，Codex 记录在 `namespace` 里的 MCP 工具也按这个格式归一，服务器名中的 `-` 和 `_` 视为相同。插件带来的 MCP 和技能目前不在此列。
